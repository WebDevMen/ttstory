# Своя графика: нарисованные сцены (`draw:`)

Кроме AI-кадров («плит»), шот может быть **нарисован кодом**: персонажи, здания, интерьеры, телефоны, карты, графики, надписи — всё это векторные «актёры» (SVG + HTML/CSS + библиотеки), которыми можно управлять до пикселя и до кадра. Никаких генераций, никаких случайностей: один и тот же `project.yaml` всегда даёт тот же ролик.

Пример целиком нарисованного ролика — [`projects/school`](../projects/school/project.yaml) («Один день в японской школе», 59 с). Каталог всех актёров с картинками — проект [`projects/gallery`](../projects/gallery/project.yaml) и картинка [`docs/img/actors.jpg`](img/actors.jpg).

## 1. Как это работает

```
project.yaml ──compile──► timeline.json (все "@слова" превращены в секунды)
                               │
                               ├─► vg.py draw  — Chromium рисует каждый кадр draw-шотов:
                               │                engine/hud/draw.html + draw/runtime.js + актёры
                               │                → build/<id>/drawn/<шот>/<кадр>.jpg + камера и якоря
                               ├─► vg.py scene — те же эффекты, что для AI-кадров: частицы, туман, свечение,
                               │                bloom, грейдинг, переходы (whip, zoom, dissolve…), зерно
                               ├─► vg.py hud   — интерфейс и субтитры поверх
                               └─► звук, сведение, MP4
```

- Рисование детерминировано: время кадра `t` — единственный вход. Анимации не «проигрываются», а **вычисляются** для каждого кадра (так же устроен Remotion, только у нас всё привязано к словам диктора и описывается в YAML).
- В одном ролике можно смешивать AI-шоты (`plate:`) и нарисованные (`draw:`) — переходы, HUD, субтитры и звук работают одинаково.
- Повторный `vg.py draw` перерисовывает **только изменённые шоты** (сравнивается хэш шота и кода актёров). `--force` — перерисовать всё.

## 2. Быстрый старт

```yaml
scenes:
  - id: hook
    text: В японской школе нет уборщиков. Вообще.
    shots:
      - id: school
        draw:
          camera: {keys: [{t: 0, z: 1.0}, {t: end, z: 1.08}]}       # медленный наезд
          layers:
            - {actor: sky, hour: 8, par: 0}                          # небо утром, неподвижно
            - {actor: school, x: 540, y: 1190, time: 8.2, plaque: "第一中学校"}
            - {actor: ground, x: -300, y: 1186, w: 1700, h: 800, color: ["#e2cfa6", "#cdb386"]}
            - {actor: tree, kind: sakura, x: 70, y: 1330, h: 560, par: 1.15}
            - {actor: badge, x: 540, y: 600, at: "@нет", enter: stamp, title: "УБОРЩИКОВ: 0", style: solid, sfx: true}
        effects:                                                     # эффекты слоя сцены тоже работают
          - {type: particles, mode: fall_loop, shape: petal, count: 30, color: [1, 0.8, 0.88]}
```

```bash
python3 vg.py voice my && python3 vg.py compile my
python3 vg.py preview my --shots            # средние кадры шотов (draw → scene → HUD)
python3 vg.py preview my --at 1.2,3.4       # конкретные моменты
python3 vg.py all my                        # готовый ролик
python3 vg.py actors my                     # список актёров (встроенные + свои)
```

## 3. Шот `draw`

| Ключ | Описание |
|---|---|
| `bg` | фон: цвет, список цветов (вертикальный градиент) или `{type: linear/radial, stops: [[0, "#fff"], [1, "#eee"]], angle, at}` |
| `world` | размер мира `[w, h]` (по умолчанию экран 1080×1920). Больше экрана — для панорам: камера ездит по миру |
| `camera` | `keys: [{t, x, y, z, roll, ease}]` — как у обычной камеры: `t` в секундах от начала шота, `"end"`, `"end-0.5"`, `"@слово"`; `x, y` — точка мира в центре экрана, `z` — зум (векторный, без потери чёткости). Плюс `sway: {x, y, roll, freq}`, `shakes: [{at, amp, dur}]`, `follow: {id, dx, dy, axis: x/y/xy, k}` (следить за актёром) |
| `layers` | список элементов (актёров) в порядке рисования: первый — самый дальний |
| `palette` | свои имена цветов: `{brand: "#ff4a7a"}` → `color: brand` |
| `depth` | глубина для эффектов слоя сцены (туман и т.п.): число или `[верх, низ]` (по умолчанию `[0.1, 0.8]`) |
| `floor` | линия пола (y мира, px): элементы с `y: floor` встают на неё; проверка ловит «висящих» и «провалившихся» (§10.3) |
| `px_per_m` | пикселей на метр: актёры с реальным размером масштабируются сами, проверка сравнивает пропорции (§10.3) |

Остальные ключи шота работают как обычно: `start`, `transition`, `effects`, `look`, `ambience`, `captions_top`, `anchors`. Координаты эффектов (`glow.at`, `particles.center`…) для draw-шотов задаются в пикселях мира и двигаются вместе с камерой.

Общие настройки для всех draw-шотов проекта — ключ верхнего уровня `draw:` (например, `draw: {palette: {...}}`).

**Параллакс.** У каждого элемента есть `par` (по умолчанию 1): `0` — неподвижен относительно экрана (небо), `0.3` — далёкий план (едет медленнее), `1` — основной план, `1.2` — передний план (едет быстрее). Это настоящая многоплановая камера: при движении камеры планы смещаются с разной скоростью.

`space: screen` — элемент в координатах экрана, камера на него не влияет (подписи, выноски, бейджи поверх панорамы).

## 4. Свойства любого элемента

| Ключ | Описание |
|---|---|
| `actor` | имя актёра (§7) |
| `id` | имя для якорей, выносок и `camera.follow` |
| `x`, `y` | позиция точки привязки актёра (у людей, зданий, деревьев — середина низа; у карточек, текста — центр) |
| `scale`, `sx`, `sy`, `rot`, `opacity`, `flip` | масштаб, растяжение, поворот (°), прозрачность, зеркально по горизонтали |
| `origin` | точка привязки: `center`, `bottom`, `top`, `left`, `right`, `top-left`… или `[x, y]` в пикселях актёра |
| `at`, `until` | когда элемент на экране (секунды или `"@слово"`). По умолчанию — весь шот |
| `enter` | появление: `fade pop zoom stamp grow grow_x grow_y slide_up slide_down slide_left slide_right rise drop fly_left fly_right fly_up fly_down spin flip_x flip_y blur wipe_left wipe_right wipe_up wipe_down iris draw`. Длительность — `enter_dur`; объект `{type, dur, ease, dist, delay}` |
| `exit` | исчезновение в конце `until`: `fade shrink zoom slide_* fall fly_* blur wipe_left wipe_right iris draw`, `exit_dur` |
| `anim` | шаги анимации (§5) |
| `float`, `bob`, `wiggle`, `sway`, `pulse`, `spin`, `blink`, `flicker`, `shakes` | «живые» циклы: парение `{amp, freq}`, подпрыгивание, покачивание `{rot, freq}`, плавное покачивание, пульсация `{amp, freq, phase}`, вращение (°/с), мигание `{freq, duty, min, phase}` (две мигалки в противофазе — `phase: 3.14`), мерцание неона, тряска `[{at, amp, dur}]` |
| `glow` | свечение: цвет или `{color, r, a}`; сила во времени — `glow_k` |
| `shadow` | мягкая тень: `true` или `{x, y, blur, color, a}` |
| `blur`, `brightness`, `saturate`, `contrast`, `hue`, `grayscale` | CSS-фильтры (можно анимировать) |
| `tilt_x`, `tilt_y`, `persp` | 3D-наклон |
| `blend`, `clip` | режим наложения, `clip-path` |
| `sfx` | звук при появлении: `true` (по типу `enter`), имя звука или `{sound, gain, offset, ...}` |
| `slot` | именованное место: `tag` (y 200) · `title` (400) · `subtitle` (540) · `main` (880) · `lower` (1200) · `footer` (1420); ставит x = 540 и `space: screen` (§10.2) |
| `fit` | автоподгонка: у текстовых актёров по умолчанию — уменьшить, чтобы влез в ширину кадра минус 48 px с каждой стороны (с учётом поворота); `fit: 700` / `fit: {w, h}` — свой блок, `fit: false` — выключить |
| `real`, `size_m`, `depth` | реальный размер (§10.3): `size_m: {h: 1.2}` — свой размер в метрах, `real: false` — не масштабировать и не сравнивать, `real: true` — масштабировать, даже если задан `scale` (тогда `scale` = глубина), `depth: 0.7` — объект намеренно дальше (меньше) |
| `air`, `ground` | `air: true` — висит намеренно (прыжок, полёт); `ground: true` то же, что `y: floor` |

`enter: draw` «прорисовывает» контуры (линии, стрелки, эскизы) — как будто их рисуют от руки.

## 5. Анимация

**Любое** свойство — и общее (`x`, `scale`, `opacity`…), и свойство актёра (`level` у батареи, `hour` у неба, `pose` у персонажа) — может меняться во времени.

**Дорожка значений** (track):
```yaml
level: [{at: 0, v: 80}, {at: "@ток", v: 25, dur: 1.2, ease: inOut}]   # первое значение действует с начала
hour: {at: "@start", from: 17, to: 20, dur: 2.5}                       # одна анимация
pose: [{at: 0, v: sit}, {at: "@Кирицу", v: stand, dur: 0.35}]          # позы плавно перетекают
text: [{at: 0, v: "07:30"}, {at: "@Восемь", v: "08:30"}]               # строки переключаются
```
Плавно интерполируются числа, списки чисел, цвета `#rrggbb` и объекты (позы); остальное переключается в момент `at`.

**Шаги `anim`** — несколько свойств сразу:
```yaml
anim:
  - {at: "@start", dur: 3.6, x: 2600, ease: linear}        # проезд поезда
  - {at: "@стоп", dur: 0.4, dy: -40, scale: 1.2}            # dx/dy — относительно предыдущего положения
  - {at: "@бросок", dur: 1.2, path: [[0, 0], [300, -200], [600, 0]], orient: true}   # по кривой
```

**Время в `at` — абсолютное.** Число в `at` у элемента, у шага `anim` и у ключа дорожки — секунды от начала **ролика**, а не шота (у камеры `t` — от начала шота). В шоте, который начинается не с нуля, `anim: [{at: 0, dur: 2, x: 900}]` закончится раньше, чем шот появится, — персонаж «уже пришёл». Пишите время словом: `at: "@Мужчины-0.2"`, `at: "@loss.start"`. `vg.py compile` предупреждает о таких анимациях.

**Easing:** `linear in out inout back expo inQuad outQuad inOutSine outBounce outElastic step` — и **любая строка GSAP**: `"back.out(2)"`, `"elastic.out(1,0.4)"`, `"power3.inOut"`, `"steps(5)"`, `"bounce.out"`.

## 6. Якоря и выноски

Ссылка на точку актёра: `"id"` (точка привязки), `"id.имя"` или `"id.имя:аргументы"`:

| Актёр | Якоря |
|---|---|
| `person` | `head`, `face`, `top`, `hand_l`, `hand_r` (вид спереди), `hand` (вид сбоку), `hip` |
| `building` | `win:этаж,столбец`, `roof` |
| `school` | `clock`, `door`, `roof`, `win:этаж,столбец` |
| `lockers`, `window_grid` | `cell:ряд,столбец` |
| `classroom` | `seat:ряд,столбец` (голова ученика) |
| `tray` | `rice`, `soup`, `main`, `salad`, `milk`… |
| `phone` | `screen` |
| `map` | `pin:номер`, `lonlat:долгота,широта` |
| `holo` | точки 3D-модели |

Где используются:
- `callout` с `target: "home.win:7,3"` — плашка с пунктиром к окну, линия следует за объектом при движении камеры;
- HUD-компоненты с `anchor: "kid.top"` — интерфейс «прилипает» к нарисованному объекту (координаты передаются из рисования в HUD автоматически); короткие имена можно задать в шоте: `anchors: {clock: "school.clock"}`.

## 7. Каталог актёров

Все размеры — в пикселях экрана при `scale: 1`. Цвета — любые: `"#ff8800"`, `"255,136,0"`, имя (`red teal amber…`) или имя из `palette`.

### 7.1 Базовые

| Актёр | Что это | Параметры |
|---|---|---|
| `shape` | фигура | `kind: rect circle ellipse line polyline polygon path star ring arc arrow triangle`, `w h r radius points d`, `fill` (цвет или `{linear/radial: [цвета], angle}`), `stroke sw dash cap`, анимируемые `fill stroke sw w h r start end` (дуга), `draw` (0..1), `morph: [{at, d, dur}]` (GSAP MorphSVG) |
| `text` | кинетическая типографика | `text` (`**акцент**`, `[цветной](red)`, эмодзи), `font: display body mono tech serif round hand jp wide` или имя шрифта, `size weight color accent italic upper align width line letter`, `stroke: {w, color}`, `shadow`, `bg: {color, pad, radius}`, `reveal: {by: char/word, mode: rise pop slam drop fade blur type scramble, stagger, dur, sync: true}` (`sync` — слова появляются ровно под голос), `highlight: [{at, until, word, color}]`, `count: {from, to, at, dur, decimals, sep}` (`text: "{n}%"`), `lines: N` + `min_size` — шрифт уменьшается, пока текст не займёт не больше N строк |
| `image` | картинка/эмодзи/иконка | `src` (файл в папке проекта), `emoji: "🍙"`, `icon: check/x/warning/heart/bolt/clock/star…`, `w h size color fit` |
| `svg` | свой SVG (из Figma, Illustrator) | `src` или `markup`, `w h`, `parts: {"#door": {fill, stroke, opacity, x, y, rot, scale, draw}}` — анимация частей по CSS-селектору |
| `group` | контейнер | `children: [...]` — вложенные элементы в координатах группы |
| `stack` | ровная стопка (§10.2) | `children: [...]`, `dir: v / h`, `gap` (px, 24), `align: center / start / end`; размеры детей перемеряются каждый кадр, шаг одинаковый, ось одна |

### 7.2 Люди

**`person`** — персонаж-марионетка с суставами (плечо, локоть, бедро, колено, корпус, голова):

| Параметр | Значения |
|---|---|
| `view` | `front` (по умолчанию) или `side` (смотрит вправо; `flip: true` — влево) |
| `look.age` | `student`, `kid` (ниже ростом, голова больше), `adult` |
| `look.outfit` | `sailor` (матроска), `gakuran`, `blazer`, `blazer_skirt`, `pe` (физкультура), `kyushoku` (халат, шапочка, маска дежурного), `kendo`, `baseball`, `teacher_m`, `teacher_f`, `suit`, `casual`; средневековье: `tunic` (рубаха с поясом), `dress` (платье со шнуровкой), `peasant_f` (крестьянка), `smith` (кузнец в кожаном фартуке), `robe` (ряса монаха), `knight` (кольчуга и табард с гербом) |
| `look.hair` | `short spiky buzz side bob long ponytail twintails bun braid tonsure`; `hair_color`; `beard: true` или цвет; `hollow: true` — «пустые» глаза без блика |
| `look` прочее | `skin` (`light mid tan dark` или цвет), `color`, `accent`, `bottom_color`, `legs: skin/socks/tights/pants`, `socks`, `shoes`, `bag: randoseru/school_bag`, `bag_color`, `hat: kid/cap/kyushoku`, `cap_color`, `mask`, `glasses`, `number`, `silhouette: true/цвет` (силуэт одним цветом) |
| `pose` (дорожка) | спереди: `stand wave raise cheer arms_up point think hold together bow sit shrug surprised`; сбоку: `stand bow sit wipe sweep swing swing_ready carry reach`; или углы суставов `{a1: [плечо, локоть], a2, l1: [бедро, колено], l2, lean, bow, sit, tilt, nod, jump}` |
| `walk` (дорожка) | шагов в секунду (`0` — стоит), `run: true` — бег |
| `face` (дорожка) | `smile neutral happy surprised talk sad sleep determined`; моргает сам |
| `talk` | `[[от, до], ...]` — рот двигается в эти моменты |
| `look_dx` | взгляд влево/вправо (−1..1) |
| `hold`, `hold_l` | предмет в руке: `tray bowl pot broom mop rag bat shinai book phone flag ladle torch candle sword shovel hammer bucket quill`; `hold_rot` — поворот предмета (предмет идёт вдоль предплечья; чтобы факел стоял вертикально при поднятой руке, `hold_rot` ≈ сумма углов плеча и локтя руки, например `a2: [70, 70]` → `hold_rot: 140`) |
| `wave_hand` | помахать поднятой рукой |

`silhouette` — простой силуэт (голова и плечи) для толпы и окон.

### 7.4 Интерьеры и предметы

## 9. Свои актёры проекта

Файл `projects/<id>/actors/<любое>.js` — каждый `export const имя = {...}` становится актёром `actor: имя` в этом проекте (и может заменить встроенный). Пример — [`projects/gallery/actors/sunburst.js`](../projects/gallery/actors/sunburst.js):

```js
export const sunburst = {
  origin: "center",                     // точка привязки x/y
  create(p, H, item) {                  // p — статические параметры из YAML
    const svg = H.svg(`<g class="rays">…</g>`, 1040, 1040);   // рисуем в своих пикселях от (0, 0)
    const tl = H.gsap.timeline({ paused: true })               // GSAP-таймлайн как функция времени
      .fromTo(svg.querySelector(".rays"), { scale: 0 }, { scale: 1, duration: 0.7, ease: "back.out(1.6)" });
    return {
      el: svg, w: 1040, h: 1040,
      update(t, it) {                   // каждый кадр; it.v("param", def) — текущее значение дорожки
        tl.seek(Math.max(0, t - it.at));
      },
      anchor(name) { return name === "center" ? [520, 520] : null; },   // необязательно
    };
  },
};
```

Пример побольше — [`projects/superuser/actors/poker.js`](../projects/superuser/actors/poker.js): окно приложения `monitor` (с вложенными актёрами), таблица `spreadsheet` с бегущими строками и подсветкой, колокол распределения `bell_curve` с выбросом, кассета со звуковой волной `waveform`. Актёры, которые пригодились больше чем одному ролику, переезжают в библиотеку — так автомат и камера наблюдения из «Как обыграть казино телефоном» стали `engine/hud/draw/actors/casino.js` (§7.7). Имена актёров в библиотеке уникальны: повтор имени в двух файлах — ошибка при загрузке.

Внутри доступно всё из `H`: цвета (`H.col`, `H.rgba`, `H.shade`), `H.svg/H.div/H.el`, `H.child(spec, container)` — вложить любой другой актёр со всеми общими свойствами, `H.track`, `H.ease`, `H.noise`, `H.rng(seed)`, `H.asset("file.png")`, `H.json(url)`, `H.anchorOf("id.name")`, `H.TL` (таймлайн, слова диктора). Свои стили — `projects/<id>/draw.css`.

Встроенные актёры — в `engine/hud/draw/actors/*.js`; новый файл подключается строкой в `actors/index.js`. Новый библиотечный актёр добавьте в галерею и обновите эталоны стенда (`vg.py bench --update`, §10.5); если у объекта есть реальный размер, объявите `size_m`; если он стоит на земле — `grounded: true`, если он сам поверхность — `surface: true` (§10.6).

## 10. Композиция

Вертикальный кадр 1080×1920, безопасные зоны TikTok/Reels/Shorts:
- **y ≈ 214** — метка сцены (HUD `marker`), ничего важного над ней;
- **y 300–1150** — главная иллюстрация и надписи;
- **субтитры** — по умолчанию y ≈ 1250; ставьте их над «полом»/дорогой/землёй, а не поверх лиц (`captions_top` у сцены или шота);
- **y > 1550** — низ закрывает подпись и ник: только декор (пол, земля, ноги);
- **x > 940 на высоте 800–1550** — кнопки справа.

Приёмы, которые делают нарисованный ролик «дорогим»:
- каждый шот двигается: наезд камеры, панорама с параллаксом, `sway`;
- 3–4 плана: небо `par: 0`, дальний план `par 0.15–0.6` (каждый — на своей земле, §10.6), основной, передний план `par 1.1–1.2`;
- живой слой: частицы (лепестки, пар, искры), ходьба, моргание, облака;
- каждое появление — на слово (`at: "@слово"`), со звуком (`sfx`);
- повторяющийся визуальный язык: одна палитра, одни шрифты, одна метка времени на все сцены;
- для смыслового акцента — крупная надпись (`text` с `reveal`) или `badge`, а субтитры в этот момент можно скрыть (`theme.captions.hide`).

### 10.1 Аккуратность: стандарт вёрстки (обязателен для каждого ролика)

Графика должна выглядеть как один продуманный макет, а не как набор кусков. Небольшие огрехи (кривой отступ, текст впритык к краю, съехавшая плашка, надпись под субтитрами) не ломают ролик, но сразу бросаются в глаза и удешевляют его. Поэтому правила ниже — обязательные, а часть из них проверяется автоматически.

**Поля и сетка**
- От края кадра до любого текста — не меньше **28 px** (лучше 40–60). Ничего не обрезается краем — ни в начале, ни в конце шота, ни при наезде или панораме камеры.
- Центрированный элемент стоит **ровно** на оси x = 540. Если элемент смещён — то явно (на 60 px и больше), а не «почти по центру».
- Стопка однотипных элементов (плашки «1-2-3», пункты списка) — одна ось выравнивания, одинаковые шаги по вертикали (100–130 px между центрами), одинаковые размер и стиль.
- Главная иллюстрация — y 300–1150; заголовки и метки — сверху (y ≈ 190–420); нижняя полоса y > 1570 и правая колонка x > 940 (y 800–1550) — без текста.

**Типографика**
- На ролик — 3–4 размера: заголовок 96–130 px, подзаголовок 56–72, плашки 40–52, подписи 30–40. Меньше **27 px** по высоте строки — не читается на телефоне.
- Длинный заголовок: `width` и проверка, что он встаёт в 1–2 строки без «висящего» слова; не помещается — уменьшите размер или сократите текст, а не уводите за край.
- Штамп с поворотом — не больше 6–8°; повёрнутый текст тоже должен поместиться в кадр.
- Одна гарнитура для заголовков (Montserrat 900), моноширинная — для дат, счётчиков и меток.

**Слои и субтитры**
- Надписи не наезжают друг на друга и на субтитры. У субтитров свой чистый пояс: если там графика — сдвиньте субтитры (`captions_top` шота) или скройте их, пока крупный текст говорит то же самое (`theme.captions.hide`).
- В кадре одновременно — один главный акцент и не больше трёх текстовых элементов (плюс субтитры).
- Элемент, который сменяется другим на том же месте, уходит полностью (`until` + `exit`) — никаких «призраков» под новым текстом.

**Единство**
- Одна палитра на ролик (`draw.palette`), одинаковые стили плашек, общие фоны и повторяющиеся элементы — через якоря YAML, чтобы одинаковое выглядело одинаково.
- Детали, собранные из нескольких фигур (ценник, весы, стол), проверяются на всех кадрах шота: части не разъезжаются при анимации и движении камеры.
- Счётчики и тексты, которые меняются во времени, остаются на своей точке привязки (движок перемеряет такие элементы на каждом кадре); проверяйте самое длинное значение.

**Проверка вёрстки: `vg.py layout`**

```bash
python3 vg.py layout <id> [--step 12]    # после compile, до полного рендера
```

Команда отрисовывает каждый draw-шот с шагом `--step` кадров, измеряет реальные границы каждого элемента и каждой строки текста, а также субтитры, и сообщает:

| | Что находит |
|---|---|
| ✗ | текст обрезан краем кадра · текст не помещается в свой блок |
| ! | впритык к краю (< 28 px) · надписи наезжают друг на друга · субтитры наезжают на надпись или на ключевой объект · текст в зоне интерфейса площадки (верх < 120, низ > 1570, правая колонка) · «почти по центру» (сдвиг 6–40 px) · мелкий текст |
| ! | **пропорции** (в сценах с `px_per_m`): объекты одного плана не соответствуют реальным размерам · **пол**: объект висит над полом или провалился · **опора** (§10.6): под основанием здания/человека/машины нет земли (виден фон) или земля на другом слое параллакса · **пустой фон**: в уличной сцене за объектами только небо · **поза** вне естественных суставов · **перегруженный кадр** (больше 5 крупных надписей) · элемент **появляется рывком** без `enter` · **низкий контраст** текста с фоном (по пикселям) · кадр **слишком тёмный / пересвечен** |
| ! | **движение** (каждый 2-й кадр): **рывок** (элемент перескочил), **дрожание** (мелкие дёрганья без заданного `wiggle`/`float`…), **мерцание** |

Шаги: `--step 12` — кадры для вёрстки (со снимками), `--mstep 2` — проход движения (`0` — выключить).

Каждое замечание — с шотом, временем и текстом элемента; кадры с разметкой (красное — ошибка, оранжевое — предупреждение, жёлтое — субтитры, синее — зоны площадки) лежат в `build/<id>/layout/issues/`, общий лист — `build/<id>/layout/sheet.jpg`. **Ролик идёт в полный рендер только при 0 ошибок и не больше 3 предупреждений**, и каждое оставленное предупреждение должно быть осознанным (например, субтитры на секунду проходят по ногам идущего персонажа). Автоматика не заменяет взгляд: после неё просмотрите превью каждого шота в начале, середине и конце (`vg.py preview --at`).

### 10.2 Слой раскладки: зоны, автоподгонка, стопки

Большинство огрехов появляется в момент ручной расстановки чисел. Поэтому движок сам держит правила:

- **Автоподгонка (`fit`)** — включена по умолчанию у всех текстовых актёров верхнего уровня (`text`, `badge`, `timetag`, `callout`, `bubble`, `card`, `checklist`, `meter`, `neon_sign`, `mail`): элемент уменьшается (никогда не растёт), чтобы вместе с поворотом поместиться в ширину кадра с полями 48 px. Слишком длинный заголовок больше не может уйти за край.
- **`lines: N`** у `text` — шрифт сам уменьшается, пока текст не займёт не больше N строк (с `width`): нет «висящих» слов и заголовков в четыре строки.
- **Зоны (`slot`)** — `tag`, `title`, `subtitle`, `main`, `lower`, `footer`: надпись встаёт ровно на ось x = 540 на свою высоту, без подбора координат.
- **Стопки (`stack`)** — плашки, пункты, карточки в столбик или в ряд: одинаковый шаг, общая ось, размеры перемеряются каждый кадр.
- **Без «уплывания»** — элементы без явного размера перемеряются после каждого изменения (шрифт загрузился, счётчик вырос) и остаются на точке привязки; кадр рисуется заново, пока раскладка не устоится, поэтому он одинаков, какой бы процесс рендера его ни рисовал.
- **Субтитры `captions_top: auto`** (у шота или `theme.captions.top: auto` для всех) — `vg.py layout` выбирает для каждого шота свободный пояс (1060–1520) с наименьшим наложением на надписи и объекты и сам пересобирает таймлайн.

Ручные координаты остаются для нестандартных композиций — проверка всё равно их контролирует.

```yaml
- {actor: timetag, slot: tag, text: "МОНТЕ-КАРЛО · 1913"}
- {actor: text, slot: title, text: "ОЧЕНЬ ДЛИННЫЙ ЗАГОЛОВОК", size: 120, lines: 2, width: 980}
- actor: stack
  slot: main
  gap: 26
  children:
    - {actor: badge, title: "САМ ПРИШЁЛ", style: solid, color: gold, size: 50}
    - {actor: badge, title: "САМ ПОСТАВИЛ", style: solid, color: gold, size: 50}
```

### 10.3 Реальные размеры, пол, позы

- **Реальные размеры.** У библиотечных актёров есть размер в метрах (человек: взрослый 1,75 · подросток 1,62 · ребёнок 1,25; автомат 1,8; парта 0,76; рулетка 0,8; карта 0,089; фишка 0,04; телефон 0,15…), свои актёры объявляют `size_m: {h}` или `{w}`. Если у шота задан `px_per_m`, такие элементы масштабируются сами, и человек у стола всегда соразмерен столу. `scale` вместе с `real: true` означает глубину (0.8 — чуть дальше), `depth: 0.7` — «намеренно дальше», `real: false` — иллюстративный размер (телефон-макет на весь экран).
- **Пол.** `draw.floor: 1500` + `y: floor` — элемент стоит на линии пола; проверка ловит актёров, которые висят над ним или провалились (`air: true` — висит намеренно).
- **Позы.** Суставы персонажа ограничены естественными диапазонами: рука не выворачивается, колено не гнётся назад, голова не отрывается; если поза выходит за предел, движок её исправляет, а проверка сообщает.

### 10.4 Раскадровка на согласование

```bash
python3 vg.py storyboard <id>     # build/<id>/storyboard/storyboard.html
```

Страница с тремя готовыми кадрами каждого шота (начало, середина, конец), текстом диктора, таймингом и замечаниями проверки. Claude публикует её как Artifact, чтобы можно было оставить комментарий к конкретному шоту; полный рендер — после согласования раскадровки.

### 10.5 Испытательный стенд актёров

```bash
python3 vg.py bench               # кадры галереи против эталонов tests/bench/
python3 vg.py bench --update      # принять задуманные изменения
```

[`projects/gallery`](../projects/gallery/project.yaml) показывает всех библиотечных актёров. `bench` рисует средний кадр каждого её шота и сравнивает с эталоном: если что-то сдвинулось, изменило размер или сломалось, команда покажет шот, долю изменившихся пикселей и картинку «эталон | сейчас | разница» в `build/bench/`. Запускайте после любой правки движка или актёров библиотеки; кривая деталь чинится один раз — и во всех будущих роликах.

### 10.6 Глубина, опора и проработанный фон

Самые частые системные недочёты нарисованных сцен — предметы, которые **висят в воздухе**, и **пустой фон**. Правила для каждой сцены (проверка `vg.py layout` ловит нарушения автоматически — `[support]`, `[backdrop]`):

1. **У каждого стоящего объекта есть опора.** Здание, человек, машина, дерево, фонарь стоят на земле, полу, дороге. Под основанием не должно быть видно неба или фона. Основание лучше чуть утопить в землю (земля рисуется после зданий и перекрывает их низ на 10–20 px).
2. **Опора — на том же слое параллакса.** Если у зданий `par: 0.35`, а у земли `par: 0.6`, при движении камеры слои едут с разной скоростью и между ними открывается щель. Поэтому **у каждого плана своя полоса земли с тем же `par`**:

   ```yaml
   x-far: &far {actor: ruin, color: "#4a2219", par: 0.35}
   x-far-ground: &far_ground {actor: ground, x: -400, w: 1900, h: 800, color: ["#3a1a12", "#160a08"], par: 0.35}
   layers:
     - {<<: *far, x: 120, y: 1390}
     - {<<: *far_ground, y: 1372}        # верх земли на 18 px выше основания — здания утоплены
   ```
   Передний план (`par` > 1) уходит за нижний край кадра — тогда опора не нужна.
3. **Фон не пустой.** В уличной сцене за главным объектом минимум 2–3 плана: дальний город / холмы / лес / руины (`par 0.15–0.25`), средний план (`par 0.3–0.6`), основной. Плюс «шум жизни»: дым, облака, огни окон, птицы, частицы (пепел, пыль, лепестки).
4. **Воздушная перспектива.** Чем дальше план, тем он светлее, менее контрастен и ближе к цвету неба у горизонта; полоса дымки (`shape` с вертикальным градиентом) у горизонта связывает планы.
5. **Линии горизонта по глубине.** Чем дальше план, тем выше его линия земли (ниже по кадру — ближе). Полосы земли дальних планов делайте широкими (`w` с запасом под панораму) и высокими — ближние планы их перекрывают.
6. **Края кадра при движении камеры.** Небо и земля шире кадра (`x: -150, w: 1380` и больше), иначе при панораме или наезде появляется полоса фона.

Когда проверка `[support]` работает: в кадре есть настоящая земля или пол (`ground`, `street`, `room`, актёр с `surface: true`, широкая фигура в нижней половине кадра или `draw.floor`). Схемы и иллюстрации на абстрактном фоне не проверяются. Основание, закрытое объектом спереди (передний ряд, стойка), висящим не считается. Разные `par` у объекта и его земли — предупреждение, только если основание у края земли (у горизонта) и за шот уплывает относительно него больше чем на 5 px.

Свои актёры проекта объявляют, к чему относятся: `grounded: true` — стоит на земле (здание, машина, завал), `surface: true` — сам является поверхностью (платформа, крыша, стол). Встроенные уже размечены (`GROUNDED`, `SURFACES` в `engine/hud/draw/core.js`).

**Чек-лист «свежим взглядом»** — смотреть начало, середину и конец каждого шота (`preview --at`), даже если проверка чистая:

- висит ли что-то в воздухе или «плывёт» относительно земли при движении камеры;
- пустой ли фон, читается ли глубина (3+ плана, дымка, светлее вдали);
- нет ли полос фона у краёв кадра в начале и в конце движения камеры;
- нет ли «штампа»: одинаковых окон, деревьев, людей подряд (меняйте `seed`, размер, позу, цвет);
- один ли источник света: блики и контровой свет со стороны солнца/огня, тени в одну сторону;
- единый ли мир: в разрушенном городе нет чистых новых машин, в ночной сцене нет дневных цветов;
- нет ли резких стыков цвета между полосами земли и случайно обрезанных краем кадра объектов (допустимо только намеренно — для переднего плана);
- соразмерны ли люди, машины, двери, окна (`px_per_m`).

> Запланировано: **ИИ-арт-директор** — отдельный агент со «свежим взглядом», который смотрит раскадровку и последовательности кадров по критериям вкуса и цельности (пропорции, композиция, «собрано из кусков»). Отложен до следующего этапа.

## 11. Как Claude собирает графику под сценарий

Попросите: «Сделай ролик своей графикой (без нейросетей) по сценарию …». Claude:
1. пишет сценарий/таймлайн и озвучивает (`voice`, `compile`), смотрит точные тайминги слов;
2. разбивает текст на шоты и для каждого придумывает сцену из актёров (§7), привязывая появления к словам;
3. если нужного объекта нет — дописывает актёра в проект (`projects/<id>/actors/`) или в библиотеку;
4. крутит цикл превью (`vg.py preview --shots`, `--at`), смотрит кадры и правит композицию;
5. проверяет графику `vg.py layout` до 0 ошибок и ≤ 3 предупреждений (§10.1) и ещё раз смотрит начало, середину и конец каждого шота;
6. собирает раскадровку `vg.py storyboard` и публикует её на согласование (§10.4);
7. рендерит, проверяет звук и контактные листы, присылает MP4.

## 12. Проблемы и решения

| Симптом | Решение |
|---|---|
| `unknown actor 'x'` | опечатка в имени или свой актёр не экспортирован (`export const x`) — `vg.py actors` |
| элемент не виден | проверьте `at`/`until`, `par` (при `par: 0` он «прибит» к экрану), координаты мира при широком `world` |
| выноска/бейдж уезжает за край на панораме | `space: screen` |
| текст японского шрифта «моноширинный» по-русски | для кириллицы используйте `font: hand` (Caveat) или Montserrat, `jp` — для иероглифов |
| `draw frame N of shot S is missing` | запустите `vg.py draw <id>` (или `scene` — он вызывает рисование сам) |
| в кадре чёрные прямоугольники 512×512 | так выглядела нехватка видеопамяти программного GPU при растеризации; рендер теперь растеризует тайлы на CPU (`--disable-gpu-rasterization` в `engine/render_hud.cjs`) |
| параметр-объект вроде `count: {from, to, at}` ведёт себя как анимация | такие ключи (`count`, `reveal`, `grow`, `routes`, `spins`, `bursts`, `rain`…) не считаются дорожками (`CONFIG_KEYS` в `engine/hud/draw/core.js`); для своего актёра не называйте ключи настроек `to`/`v` |
| долго перерисовывается | `vg.py draw` пропускает неизменённые шоты; правьте по одному шоту и смотрите `preview --at` |
| плашка или счётчик «съезжает» в сторону от точки привязки | раньше элементы без явного размера мерились один раз (до загрузки шрифта / при коротком значении счётчика); теперь движок перемеряет их каждый кадр — перерисуйте шот; для своих актёров возвращайте `w`/`h`, если размер известен |
| персонаж не входит в кадр, а уже стоит на месте; анимация «не играет» | число в `at` — абсолютное время ролика: в шоте не с начала ролика пишите `at: "@слово"` или `"@сцена.start"` (compile предупреждает: «кончается раньше начала шота») |
| `vg.py layout` ругается на «почти по центру» | поставьте элемент ровно на x = 540 или сместите явно (≥ 60 px) |

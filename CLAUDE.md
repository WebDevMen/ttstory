# TTStory — vertical video engine

- Purpose: produce 9:16 TikTok/Shorts/Reels videos from a script. Each video = `projects/<id>/project.yaml` + keyframe images in `projects/<id>/plates/`.
- To write a script for a topic (research, hooks, timed voice-over, shot plan, packaging), follow `.claude/skills/write-script/SKILL.md`; methodology and every rule: `docs/SCRIPTING.md`. Scripts live in `projects/<id>/script.yaml` (+ rendered `script.md`); code in `engine/script/` (knowledge base in `engine/script/data/*.yaml`). Reference scripts: `projects/blackout` (script only), `projects/shadow` (fiction «Без тени» rewritten as one ~3-min story by the clarity rules: one POV heroine, character lines in their own voices, a dilemma, a clue planted three times), `projects/shadow1–3` (the old series v2 — an ANTI-example: it passed the old checks but viewers could not follow the plot; clarity rules in `docs/SCRIPTING.md` §14.6, the user's sample of a good story video analysed in `docs/examples/shelter14.md` — a feel reference, never a template), `projects/slots` and `projects/superuser` (series «Аферы»: script → finished video; casino/card actors live in the library, `engine/hud/draw/actors/casino.js` and `cards.js`; project actors example: `projects/superuser/actors/poker.js`).
- To make or change a video, follow `.claude/skills/make-video/SKILL.md`. The process and quality bar are in `docs/MANUAL.md`; every YAML key is in `docs/REFERENCE.md`.
- Reference projects: `projects/tanker` (sci-fi, dynamic), `projects/tea` (painted, calm) and `projects/school` (100% code-drawn, no AI images). `projects/gallery` is the visual catalog of draw actors. `projects/_template` is the starting skeleton.
- Graphics methods — the user chooses one per video (rule: `docs/MANUAL.md` §0 «Способ графики»):
  - `draw` — **default**: own code-drawn graphics, no AI images: actors in `engine/hud/draw/actors/*.js` (+ `projects/<id>/actors/*.js`), runtime in `engine/hud/draw/`, rendered by `vg.py draw`. Docs: `docs/DRAW.md`; references: `projects/school`, `slots`, `superuser`, `blame`.
  - `motion` — AI illustrations (`plate:`, one style bible, spends Figma AI credits) + motion graphics (`motion:`, Remotion engine in `engine/motion/`, blocks laid out by flexbox with spring animation). Docs: `docs/MOTION.md`; reference: `projects/proverbs`. Render graphics frames with `vg.py motion <id> [--frames …]`.
  - `plates` — AI keyframes with 2.5D parallax (`projects/tanker`, `projects/tea`); `mixed` — a combination.
  - Pick the method from the request (explicit words, «как школа / как пословицы / как танкер», an existing project's `meta.style`). If the request does not make it clear, ask the user once (draw recommended) before writing the script or project; if nobody can answer, use `draw`. Never switch an existing project's method on your own.
- Commands: `python3 vg.py <doctor|new|voice|compile|prep|grid|preview|motion|draw|layout|storyboard|actors|scene|audio|hud|mux|qa|all> <id>`, `python3 vg.py bench [--update]`; scripts: `python3 vg.py script <formats|new|check|render|project>`. Set up with `./setup.sh`, then `source .venv/bin/activate`.
- Engine code: `engine/` (Python: tts, compile, prep, scene, audio, mux, qa; motion graphics in `engine/motion/` (Remotion, React/TypeScript, `npm ci` there); HUD and draw runtime in `engine/hud/` — HTML/CSS/JS + GSAP, Lottie, rough.js, D3, three.js (vendored in `engine/hud/vendor/`) rendered in headless Chromium by `engine/render_hud.cjs`).
- `build/` (intermediate frames, caches) and `models/` (ONNX weights) are git-ignored. Finished videos go to `out/<id>.mp4`; keep them under 100 MB.
- Design quality is mandatory for every video: graphics must look like one careful layout — margins ≥ 28 px, centred items exactly on x = 540, consistent type scale and spacing, no text cut by the frame, no overlaps with other texts or captions, nothing drifting during animation. Standard: `docs/DRAW.md` §10.1; check with `python3 vg.py layout <id>` (0 errors, ≤ 3 deliberate warnings; it also checks proportions, floor contact, support — every grounded object needs a surface under its base on the same parallax layer — empty backdrops, poses, contrast and motion) and by eye before every full render.
- Scene believability is mandatory too, for every frame you make (any method, any topic), without the user having to point it out: nothing hangs in the air (each background plane has its own ground with the same `par`, bases sunk into it), no empty backdrops (outdoors: 3+ depth planes, haze, life such as smoke/lights/particles), aerial perspective, sky and ground wider than the frame for camera moves, no repeated stamps, one light direction, one consistent world. Rules and the «fresh eyes» checklist: `docs/DRAW.md` §10.6 (AI images: `docs/MANUAL.md` §14). Look at the start, middle and end of every shot before showing frames to the user.
- When the user points out a defect, fix it in the project AND generalize it: add the rule to the docs/checklist above and, if it can be detected, a check to `engine/layout.py` (or `engine/qa.py`), then verify the check catches the old state. A defect the user had to mention once must never need mentioning again. For `motion:` the engine enforces this layout (flex column, auto-fit titles, shrink-to-fit stage); for `draw:` compose with the layout layer (`docs/DRAW.md` §10.2–10.3). Before the full render publish `python3 vg.py storyboard <id>` for approval. After any change of the engine or library actors run `python3 vg.py bench` (gallery vs `tests/bench/`). The AI art director is planned but deferred — do not build it until asked.
- Run long steps (`prep`, `scene`, `hud`, `all`, `mux`) in the background with a long timeout. `prep` and `voice` resume and skip finished work.
- User-facing docs are in Russian. Keep it that way.
